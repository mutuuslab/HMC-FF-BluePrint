# 12장. 롤백 및 긴급 대응 체계

> **제3편. 운영 모델** | 대상 독자: SRE, OTA 운영, Safety, 경영층

---

## 12.1 3-Level 롤백 메커니즘

| | Level 1 | Level 2 | Level 3 |
|---|---|---|---|
| **방법** | COTA 플래그 비활성화 | UCM SW 롤백 | 딜러 ECU 리플래시 |
| **시간** | **<5분** | 20~30분 | 수시간~수일 |
| **코드 변경** | 없음 (구성만) | 이전 버전 복원 | 수동 리프로그래밍 |
| **차량 재시작** | 불필요 | 필요 | 필요 |
| **사용자 영향** | 최소 (기능 비활성) | 중간 (재시작) | 높음 (딜러 방문) |
| **오프라인 차량** | 다음 연결 시 | 다음 연결 시 | 딜러 방문 시 |
| **트리거** | 자동/수동 | 자동 에스컬레이션 | 수동 에스컬레이션 |

> **경영층 핵심:** Level 1 COTA 킬스위치로 5분 이내에 전 차량 원복 가능. 이것이 FF 플랫폼의 "persistent undo button".

---

## 12.2 에스컬레이션 경로

```
이상 감지 → 심각도 분류
  ├─ 경미(Minor) → Level 1 COTA 킬스위치 → 해소? → Yes → RCA
  │                                         └── No → Level 2
  ├─ 심각(Severe) → Level 2 UCM SW 롤백 → 해소? → Yes → RCA  
  │                                         └── No → Level 3
  └─ 치명적(Critical) → Level 3 딜러 리플래시 → RCA
```

---

## 12.3 Level 1 상세 — COTA 킬스위치 (<5분)

1. Ops Flag → disabled
2. COTA 구성 패키지 생성
3. SSE 긴급 푸시 → 전체 플릿
4. 인메모리 + NVRAM disabled
5. 비활성화 검증 (텔레메트리)

---

## 12.4 Level 2 상세 — UCM SW 롤백 (20~30분)

1. 이전 SW 버전 지정
2. V-UCM 롤백 트리거
3. 차량 재시작 스케줄링
4. 부팅 검증 + DTC 클리어

---

## 12.5 Level 3 상세 — 딜러 리플래시 (수시간~수일)

1. 서비스 불레틴 발행
2. 딜러 네트워크 통보
3. 수동 ECU 리프로그래밍
4. 최종 검증 + 고객 인수

---

## 12.6 인시던트 관리

- **5-Why 근본원인분석 (RCA)**
- 플래그 처분 결정:
  - 수정 → CI/CD 재진입 → 재배포
  - 영구 비활성화 → 코드 제거 스프린트
